# Switch Time — 集中を、切り替える。

iPhone・iPadでホーム画面に追加できる、切り替え式ストップウォッチです。

## 最初の一度だけ：公開する

1. [Settings → Pages](https://github.com/tarryaa/time/settings/pages) を開きます。
2. **Build and deployment → Source** を **Deploy from a branch** にします。
3. **Branch** を **main**、フォルダを **/ (root)** にして **Save** を押します。
4. 数分後、 **https://tarryaa.github.io/time/** にアプリが公開されます。

このリポジトリのルートにアプリ本体を配置済みです。インストールやビルドは不要です。以後はファイルを更新するとGitHub Pagesが自動で反映します。

## ホーム画面に追加

**iPhone / iPad:** [公開URL](https://tarryaa.github.io/time/) をSafariで開く → 共有 → **ホーム画面に追加** → 追加。

**Android:** Chromeで公開URLを開く → メニュー ⋮ → **ホーム画面に追加 / アプリをインストール**。

GitHubのコード画面ではなく、GitHub Pagesの公開URLを開いてください。

## タイマー

- カードをタップして開始。別のカードをタップすると、前を止めて次を開始します。
- 最大12個。名前と色を編集でき、組み合わせをプリセットとして保存できます。
- 個別時間と合計時間が自動連動。「一時停止」で全体を止め、任意のカードから再開できます。
- リセットすると全タイマーと合計が0になり、計測が停止します。
- 名前・色・組み合わせをプリセットとして端末に保存できます。
- iPhone・iPad・PC対応。オフラインで起動でき、対応端末では画面の保持も可能です。

### アプリ終了・電源オフの間の計測

動作中のタイマーは、保存した開始時刻と再び開いた時刻の差から経過時間を復元します。アプリを完全終了した場合や端末の電源がオフだった場合も、その間の時間を加算します。休憩したい場合は、閉じる前に明示的に一時停止してください。

電源オフ中にプログラムが実行されるわけではありませんが、再び開くと、時間の表示は継続していた場合と同じになります。端末の時計を手動変更すると計測に影響する場合があります。

## リズム通知（等間隔の音）

タイマー画面にある **リズム通知** の専用スイッチをオンにした間だけ通知します。ストップウォッチの一時停止とは独立して動きます。

歯車ボタンから以下を設定できます。

- **間隔:** 秒・分・時間で自由入力。1秒〜24時間。
- **音量:** 0〜100%。端末本体の音量も反映されます。
- **音:** トン / やわらかなベル / 小さなクリック / ピッ / しずく。
- **自分の音:** 音声ファイル（MP3・WAVなど）も使用可能。10MB以下、先頭3秒を使います。対応形式はブラウザに依存します。
- **試聴:** 選んだ音と音量で確認できます。

初期状態はオフです。バイブ機能はありません。

## 経過時間の読み上げ

専用の「開始」ボタンから、読み上げ用の時間を独立して計測します。間隔は秒・分・時間で設定できます。

- 5分ごと：**5分 → 10分 → 15分**
- 10秒ごと：**10秒 → 20秒 → … → 1分10秒**
- 1時間を超えると：**1時間5分** のように読み上げます。
- 「ストップ」で声と計測を停止、「再開」で続きから計測します。
- ↺ で読み上げの時間を0に戻します。各ストップウォッチの時間は変えません。
- 音量と読み上げ速度を設定でき、試聴もできます。

短い間隔で長い言葉を読み上げる場合は、重ならないよう次の読み上げをスキップします。通知音と読み上げが重なる場合は読み上げを優先します。

### 音楽・YouTubeを聴きながら使う

読み上げの歯車 → **他の音声との再生 → 音楽・動画と同時再生** を選び、設定を保存してください。初期設定も同時再生優先です。この設定はリズム通知と読み上げに共通です。

対応ブラウザでは Audio Session API の `ambient` を再生前に設定して、音楽・動画に重ねる再生を要求します。同時再生モードでは、このアプリからロック画面のメディア操作やタイトルを登録しません。

**iPhone・iPadで他アプリの音楽・YouTubeと実際に同時再生するテストは未実施です。** 同時再生の可否は端末・OS・ブラウザと相手のアプリに依存します。API非対応の場合は、設定画面にその旨を表示し、排他的な再生へ自動で切り替えません。

iPhone・iPadでは消音モードを解除して使ってください。同時再生を優先した場合は、画面ロックや別アプリへの切り替えで読み上げが止まることがあります。iPadではSplit Viewなどで両方の画面を表示すると使いやすくなります。

**画面ロック中の再生** を選ぶと、従来のメディア再生を優先します。このモードは他の音楽・動画を停止させる場合があります。Web版では、他アプリとの同時再生とロック中の継続を両方保証できません。

音楽を先に再生 → Switch Timeで読み上げ開始 → 必要に応じて音楽側の音量を調整、の順で使用してください。OSに音声を中断された場合も経過時間は継続し、アプリに戻って「音声を再開」で続けられます。

技術資料： [Audio Session仕様](https://www.w3.org/TR/audio-session/)、[WebKitの同時再生・背景時の挙動](https://bugs.webkit.org/show_bug.cgi?id=264473)。

### 画面を消してロックした場合

通知音と日本語の読み上げを事前にMP3へ組み込み、HTMLの音楽プレイヤーで連続再生します。ロック中の再生はJavaScriptの定期タイマーやブラウザの音声合成に依存しません。

開始すると、6時間分の音声を準備し、さらに続きの6時間分も準備します。端末側の処理のため、最初の準備に数秒かかる場合があります。最初の起動時は日本語の音声素材を取得します。一度開いてキャッシュされるとオフラインでも利用できます。

画面ロック後も、通常のメディア再生として通知音と読み上げの継続を目指した方式です。**iPhone・iPadのロック中の実機テストは未実施です。** ブラウザやOSの省電力制限、他の音声アプリ、電話などにより再生が停止する場合があります。その場合はアプリを開き、「音声を再開」を押してください。再表示時には経過時間とのずれを補正します。

ロック中の再生を優先するモードでは、ロック画面のメディア停止ボタンから通知音と読み上げを両方停止できます。

### アプリの完全終了と端末のシャットダウン

アプリを完全終了・タブを閉じる・端末を完全にシャットダウンした場合は音声を再生できません。ストップウォッチと読み上げの計測状態は開始時刻から復元します。閉じていた間の音声を後からまとめて再生することはありません。

### イヤホンについて

イヤホン検知の機能はありません。イヤホンでもスピーカーでも、端末の出力先に従って再生します。イヤホンを外すとスピーカーへ切り替わる場合があります。

## 保存

時間・プリセット・通知音設定はブラウザの `localStorage`、自分の音声ファイルは `IndexedDB` に保存します。サーバーへ計測データや音声ファイルを送信しません。端末間の同期はありません。

Safariとホーム画面版などで保存領域が別になる場合があります。使い始めた後は同じ開き方で使ってください。ブラウザのデータを削除すると、保存内容も消えます。

## 開発・動作確認

```sh
node --test tests/*.test.mjs
python -m http.server 8080
```

`http://localhost:8080` を開きます。PWAにはHTTPSまたはlocalhostが必要です。フォントはオンライン時にGoogle Fontsから取得し、オフラインでは端末の標準フォントを使用します。

更新時は `sw.js` の `CACHE` 名を変更してください。新しいバージョンは、開いているアプリの画面を全て閉じた後の再起動で適用されます。
